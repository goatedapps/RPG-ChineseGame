The P2 pack is large enough to shape the architecture now. P2 and P5 will play through the same seven-region world, cast, quests, bosses, and Great Forgetter storyline. The safest next move is to preserve the P5 prototype as a reference, rebuild one tested system at a time, and prove that the shared Region 1 works with both curriculum packs before expanding the world.

02 / Target architecture

One engine and one world, with interchangeable curriculum packs.

The loader combines the shared campaign with the selected school level’s words, questions, stories, feature flags, and tuning. Maps and story assets are built once.

03 / Recommended sequence

Prove reuse before building more world.

1

Foundation and content pipeline

Create the modular shell, normalize both source packs, extract local Hanzi data, and establish save migrations, events, time, and deterministic random helpers.

Exit: P2 and P5 both load in a content lab; validation and unit tests pass.

2

Learning core

Move mastery, spaced review, question selection, writing, audio, and answer feedback into pure modules with feature-aware adapters.

Exit: any supported P2 or P5 word can run all enabled skills without the world UI.

3

P5 Region 1 parity

Rebuild the existing village, battles, school, Reading Hall, shop, parent controls, and boss against authored data while checking behavior against the prototype.

Exit: the new build can replace the prototype for the complete Region 1 loop without losing saves.

4

P2 in the same Region 1

Map P2 Lessons 1–3 into Scholar Village, Camping Forest, Misty Path, and Kitchen Garden. Reuse the same villagers, quests, Muddle King story, and maps while adapting learning content, text density, and combat tuning.

Exit: switch P2 ↔ P5, play the same Region 1 with the appropriate curriculum, and restore each independent save. No duplicate world assets exist.

5

Tablet pilot and hardening

Observe first-use navigation, writing, battle comprehension, passage reading, parent switching, offline use, and recovery over several sessions.

Exit: blockers are fixed and there is evidence to choose which campaign expands first.

6

Expand the shared world

Build Regions 2–7 once. Each region reads the active level’s lesson range, stories, questions, and tuning while keeping the same locations, residents, quests, and plot.

Exit: every new region works with P2 and P5 without duplicating maps or narrative content.

05 / Controls and risks

What needs protection during the rebuild.

Keep the prototype availableThe published P5 prototype remains usable until the modular build reaches feature parity. It supplies the comparison behavior for migration tests.
Preserve saves explicitlyThe new save loader needs tested migration from the current P5 format, separate P2 and P5 keys, backups, checksum validation, and export/import recovery.
Respect uneven P2 coverageFeature flags and shared-campaign validation prevent small question pools from becoming repetitive gates or causing missing-content failures.
Avoid a big-bang rewriteMigrate content, learning, saves, world, battle, and UI in thin working slices. Each slice gets a reviewable page and focused tests before the next system moves.
Work already incorporated: P2 and P5 now live under content/source/, levels.json records source and world-mapping readiness separately, and npm run validate:content audits both packs. The specification now makes the seven-region world and main storyline shared across every school level.
